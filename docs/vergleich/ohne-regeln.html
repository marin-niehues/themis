Plugin für Claude Code

Ein Regelwerk für das ganze Team.

themis lädt bei jedem Sessionstart eure gemeinsamen Regeln aus GitHub. Claude schreibt danach Texte, Code und Oberflächen so, wie euer Team es festgelegt hat, und lässt die üblichen KI-Muster weg.

Man erkennt KI-Text nach zwei Sätzen.

Wer täglich mit Claude Code arbeitet, kennt die Muster: Einleitungen, die nichts sagen, Aufzählungen mit immer drei Punkten, Kommentare, die den Code nacherzählen, Oberflächen mit Farbverlauf und Emoji.

Viele Teams lösen das mit einer CLAUDE.md pro Projekt. Nach ein paar Wochen gibt es dann zehn Fassungen, und keine ist aktuell.

  • Text„In der heutigen schnelllebigen Welt …“ als erster Satz
  • TextGedankenstriche, Doppelpunkte und Fettdruck in jedem Absatz
  • CodeKommentare wie // Schleife über alle Einträge
  • CodeFehlerbehandlung für Fälle, die nicht eintreten können
  • OberflächeVioletter Verlauf, drei Karten mit Icon, „Loslegen 🚀“

So funktioniert es

themis hängt sich in den Start einer Claude-Code-Session. Ihr müsst danach nichts mehr tun.

Session startet

Beim Aufruf von claude holt themis die Regeldatei aus dem GitHub-Repository.

Regeln gehen in den Kontext

Die Datei wird Claude als Kontext mitgegeben, bevor die erste Anfrage kommt.

Claude hält sich daran

Texte, Code und Oberflächen folgen den Regeln, in jedem Projekt und bei jeder Person im Team.

Was die Regeln abdecken

Die Regeldatei ist eine einfache Textdatei. Sie beschreibt, was Claude schreiben soll und was nicht.

Texte

Commit-Nachrichten, Dokumentation, Release-Notes, E-Mails. Kurze Sätze, keine Füllwörter, keine Floskeln am Anfang und am Ende.

statt „Gerne helfe ich dir dabei!“
direkt die Antwort

Code

Kommentare nur dort, wo sie etwas erklären, das der Code nicht zeigt. Keine Abstraktion auf Vorrat, keine Hilfsfunktion für eine einzige Stelle.

statt // erhöht i um 1
direkt i++

Oberflächen

Ruhige Typografie, klare Abstände, Farben mit Zweck. Kein Standardlook, der aussieht wie jede zweite generierte Seite.

statt „Jetzt loslegen 🚀“
direkt „Installieren“

Eine Datei, ein Ort, alle Sessions.

Die Regeln liegen in einem GitHub-Repository und nicht verstreut in einzelnen Projekten. Wer eine Regel ändert, macht einen Commit. Ab der nächsten Session gilt die Änderung bei allen im Team.

Weil alles in Git liegt, seht ihr, wer was wann geändert hat, und könnt über Pull Requests darüber sprechen.

  • Jemand bemerkt ein Muster, das stört.
  • Neue Regel als Pull Request ins Repository.
  • Das Team prüft und führt zusammen.
  • Die nächste Session lädt die neue Fassung, bei allen.

Installation

Voraussetzung sind Claude Code und die GitHub-CLI gh mit Zugriff auf das Repository.

  1. Repository nach ~/themis klonen.
  2. Installationsskript ausführen.
  3. Neue Claude-Code-Session starten. Die Regeln sind ab jetzt dabei.
Terminal
$ gh repo clone marin-niehues/themis ~/themis
$ ~/themis/install.sh

Häufige Fragen

Muss ich in jedem Projekt etwas einrichten?

Nein. themis wird einmal pro Rechner installiert und greift in jeder Claude-Code-Session, egal in welchem Projekt.

Was passiert mit unserer bestehenden CLAUDE.md?

Sie bleibt, wie sie ist. Projektspezifische Hinweise gehören weiter dorthin. themis liefert die Regeln, die für alle Projekte gleich sind.

Wann wird eine geänderte Regel wirksam?

Beim nächsten Start einer Session. Laufende Sessions behalten die Fassung, mit der sie gestartet sind.

Können wir eigene Regeln verwenden?

Die Regeldatei ist Text in einem Git-Repository. Ihr könnt sie bearbeiten wie jede andere Datei und Änderungen per Pull Request einbringen.
